# MC6839 floating-point linkage (scope / design)

Plan: replace the Microware-format `cfloats.a` helpers with the **MC6839** IEEE
FP package. MC6839 is IEEE 754 binary64/binary32 — the same format clang's
`double` uses on the host — so the compiler's constant emission (now fixed,
commit 3d60db3) already produces exactly the bytes MC6839 wants. This doc scopes
the runtime linkage; the shim runtime itself is the next step.

## The module

`ROM/Float09.bin` in the nfp09 repository
(`git clone https://github.com/markrvmurray/nfp09.git`; 8192 bytes) is a valid OS-9
module:

| Field | Value |
|-------|-------|
| Name | `FPO9` |
| Type/lang | `$B1` (USR-B, 6809 obj) — not a program; `F$Load`/`F$Link` work |
| Attr/rev | `$82` (reentrant, rev 2) |
| Size / CRC | `$2000` / good |

It's an OS-9 *multimodule*: after the 9-byte header is an entry table mapping
named entries to offsets (confirmed from nfp09's `romsrc/frnbak.s` and the binary):

| Entry | Offset from module base | Max stack |
|-------|-------------------------|-----------|
| `REG`  (FPREG)  | **`$3D`** | 155 bytes |
| `STAK` (FPSTAK) | **`$3F`** | 185 bytes |

Both are `BRA` into the register / stack front ends.

## Calling convention (register ABI)

`LBSR FPREG; FCB <opcode>` — the package reads the opcode through the LBSR-saved
return PC, advances it past the FCB, and returns to the byte after. A `JSR
[ptr]` works identically (also pushes the return PC). Args: pointers in U/Y/X,
FPCB pointer in D (see nfp09's `abi/nfp09-abi.s` for the authoritative ABI).

Gotchas (from the llvm-mc6809 Bug #162 notes):
- **`PSHS U,Y` before the call, `PULS` after** — the ROM's exit restores U/Y to
  their values *at the call*, and uses them as scratch internally.
- **FPCB control byte must be nonzero.** For double: `CTL = $29`
  (precision=double `$20` | NRM `$08` | round-nearest `00` | affine `$01`).
- **Verify opcodes against `equates.s`**, not docs. Key ones:
  `FADD $00  FSUB $02  FMUL $04  FDIV $06  FCMP $8A  FNEG $20`,
  int↔float `FFLTS $24 / FFLTD $26` and `FFIXS $16 / FFIXD $18`, `FMOV $9A`.
  A bad opcode silently dispatches into the wrong table.

## crt0 linkage (DONE — commit adds fpinit.a / fpdummy.a / crt0 hook)

`crt0.s` calls `_fpinit` after zeroing the data area / before `main`, and
`_fpterm` after `main` returns.  Two link-time variants resolve those calls,
selected exactly like the printf `pflinit`/`pfldummy` idiom:

- **`fpinit.a`** (real) — for programs that use FP.  `F$Link "FPO9"` (type
  `$B1`); on `E$MNF`, `F$Load "/DD/Modules/FPO9"`.  Then store `_fpmod` =
  module base, `_fpreg` = base+`$3D`, `_fpstak` = base+`$3F`, and an FPCB at
  `_fpcb` with `CTL=$29`.  `_fpterm` does `F$UnLink`.  If FPO9 can't be linked
  or loaded it leaves `_fpreg` = 0 and returns (see Integration, item 2).
- **`fpdummy.a`** (no-op `_fpinit`/`_fpterm`) — the default; in `libc3.a` because
  none of the cross-built c3 tools use FP.  A no-FP program never links FPO9.

`_fpmod`/`_fpreg`/`_fpstak`/`_fpcb` are exported from `crt0.s`'s data area (bss,
Y-relative, beside `_flacc`); the FP wrappers reach them as `name,y`.  The real
`_fpinit` is meant to be bundled into the same object as the FP helper wrappers
(below) so any FP operation pulls it in automatically.

The MC6839 module file must be installed as `/DD/Modules/FPO9` (the file `fpo9`
from `Float09.bin`), or pre-loaded into the module directory at boot so the
`F$Link` resolves without the `F$Load` fallback.

NOTE: this covers the **lwbackend `crt0.s`** path (the cross-built tools / host
cross-compile).  Programs compiled *on-target* use Microware's `cstart.r`
(`lib/sys.a/cstart.a`); that startup needs the same `_fpinit`/`_fpterm` hook when
the on-target FP shim lands.

## Shim runtime (DONE — `lwbackend/fpwrap.a`)

`fpwrap.a` implements every FP helper the compiler emits (the full set from
`comp/codgen.c`) over the MC6839 register ABI, holding IEEE doubles in `_flacc`
and the c3 operand stack:

| c3 helper(s) | MC6839 op | opcode |
|--------------|-----------|--------|
| `_dadd` `_dsub` `_dmul` `_ddiv` | FADD/FSUB/FMUL/FDIV | $00/$02/$04/$06 |
| `_dcmpr` | FCMP (X=$0011 param; result→CC, signed) | $8A |
| `_dneg` | FNEG | $20 |
| `_itod` / `_dtoi` | FFLTS / FFIXS (16-bit int) | $24 / $16 |
| `_ltod` `_utod` / `_dtol` | FFLTD / FFIXD (32-bit int; utod zero-extends) | $26 / $18 |
| `_dtof` / `_ftod` | FMOV (U=$0010 / $0001 precision word) | $9A |
| `_dstack` | stack push (no FP) | — |

Each wrapper saves the data base (Y), stashes the FPREG entry on the 6809 stack
and dispatches via `jsr [n,s]; fcb <op>` (so X stays free for the result
buffer), then restores Y and returns X→`_flacc`.  The c3 binary convention (op1
pushed via `_dstack`, X→op2, op1 cleaned on return) is handled in the teardown.

**Every wrapper is verified on usim09batch** against known IEEE-754 binary64
values — see `lwbackend/fpbench/` (`dyad_bench.s`, `rest_bench.s`,
`conv_bench.s`; build with `lwasm --format=srec`, run with `usim09batch`).  The
benches embed `Float09.bin` and set `_fpreg = rom+$3D` directly (bare 6809, no
OS-9), exactly mirroring what `fpinit.a` does via `F$Link`.  FPCB CTL=$29 and
$20 both compute correctly for finite values.

`fpwrap.a` is RMA source: it assembles on-target with `rma` directly, and on the
host through `c3lw.awk | lwasm` (it externs only `_flacc`/`_fpcb`/`_fpreg` from
crt0).  The compiler evaluates FP in double, so doubles are the path that
matters; `_dtof`/`_ftod` cover float storage conversions.

### Integration (partly done)
1. **`lib/sys.a/cstart.a`** now has the `_fpreg/_fpstak/_fpcb/_fpmod` data-area
   globals (beside `_flacc`) and calls `_fpinit` before `main` / `_fpterm` after
   — the on-target parallel of `crt0.s`.  (cstart.a is rma-only on-target; the
   host c3lw filter can't assemble it because of its `pushzero` macro, unrelated.)
2. **`fpinit.a` is non-fatal** on F$Link/F$Load failure (leaves `_fpreg`=0 and
   returns) — required because cstart/crt0 call it for *every* program, so a
   missing FPO9 must not kill no-FP programs.  F$Link finds a resident FPO9
   cheaply; F$Load from `/DD/Modules` is the one-time fallback.
3. **`build/os9/mkdsk.sh`** installs `Float09.bin` as `/DD/Modules/FPO9`.
4. **NOT YET: the on-target library.**  `build/os9/mklibs` mirrors the curated
   `buildlibc.sh` module set, so `clib.l` carries only the no-op `fpdummy.a`;
   `fpwrap.a`/`fpinit.a` are neither staged on the disk nor built into it.
   Programs compiled on OS-9 therefore can't use FP yet.

Still to do: add `fpwrap.a` + `fpinit.a` to the on-target library (and to the
host `c3-ld` link), then compile and run a `double` program on real/emulated
OS-9.  The host flat-binary smoke test in `fpbench/` already proves
